## Near-Close Timing RCA

The near-close condition was a live-path timing/visibility issue, not a Matrix
bridge issue and not an accepted-stale trade issue. Around 15:30 IST the target
stream tail stopped advancing; the passive runner later reported
`decisions_deferred_stream_catchup` with `reason=feed_not_caught_up`,
`feed_latest_age_seconds` above the 120s catch-up limit, and
`latest_tail_report.bytes_read=0`. The stale entry candidates for TITAN, DLF,
PNB, PHOENIXLTD, and YESBANK were emitted around 15:30 with entry timestamps
around 15:14:54-15:14:58, so the stale-entry guard correctly suppressed them.

The 15-minute monitor did not surface this earlier at symbol level because the
outer heartbeat sampled status on a coarse cadence, while the existing watchdog
alerts only exposed generic feed/clock age. The symbol-level stale entries did
not exist until the 15:30 close handling window, and the earlier 15:21
`clock_eval_stale` warning was not enough to show the later stale-entry
suppression set.

## Fixes Applied

- Rebuilt Matrix from corrected v2 selected-leg ledgers after detecting active T2
  contamination in Matrix state.
- Added post-install audit checks for Matrix active T2 parity against v2 ledgers.
- Added audit failure checks for Matrix positions that are both active and
  selected-exited.
- Updated Matrix selected-exit reconstruction so nested T2 exits inside
  `paper_exit` rows are handled as selected T2 exits.
- Updated the live watchdog to report decision catch-up deferrals, missed-not-ready
  clock reports, stale open-position counts, and compact latest decision context
  directly in watchdog status/alerts.
- Patched open-position evaluations under `model_clock_entry_symbols` to use the
  compact model-clock position updater instead of the full retained-history
  fallback path.
- Restored the Aug27 consolidated post-EOD baseline manifest so the next EOD
  appends only the next trade date.
